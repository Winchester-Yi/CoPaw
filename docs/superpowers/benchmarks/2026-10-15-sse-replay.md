# SSE 有界重放测量

运行 `venv/bin/python scripts/benchmark_sse_replay.py --help` 查看参数。原始结果为 [旧内核](2026-10-15-sse-legacy.json) 与 [共享日志](2026-10-15-sse-replay.json)。这是本机内核模拟：4 个租户，每个发送 5000 条约 1 KiB 的独立事件，各有一个及时消费和一个完全停滞的订阅；不包含 HTTP、模型、数据库或跨 Pod 路由。旧内核的历史与慢队列共享字符串引用，没有假定复制两份 payload。

| 指标 | 旧内核模拟 | 共享日志 |
|---|---:|---:|
| 总耗时 | 0.0635 s | 1.5965 s |
| 进程 RSS 采样峰值 | 53.30 MiB | 24.92 MiB |
| 慢订阅队列条目 | 20000 | 0 |
| 临时日志及索引 | 0 | 20.21 MiB |
| stream worker 完成任务 | 0 | 40000 |

新内核通过磁盘存储换取有界 payload 内存；本次无节流模拟中耗时约为旧内核的 25 倍。它不能证明吞吐改善。worker 最近 2048 个样本的排队 p95/p99 为 0.073/0.081 ms，执行 p95/p99 为 0.052/0.088 ms。日志关闭后，日志占用、活跃日志/订阅和批次内存计数均归零。

旧内核 loop 延迟只有 10 个样本，新内核有 317 个；其 p95/p99 不具备足够可比性，不能将 2.405 ms 与 0.076/0.098 ms 解释为生产延迟收益。RSS 采样也不覆盖所有瞬时峰值。Linux 容器需进一步测量真实网络慢消费者、长期并发、磁盘延迟和容器总内存；tmpfs/page cache 可能计入容器内存，不能用进程 RSS 代替容器预算。

本轮优先保证完整顺序、隔离慢订阅和明确恢复。后续若生产指标表明日志吞吐不足，可另行评估有界追加批次；不在当前变更中引入额外 writer 状态机。
