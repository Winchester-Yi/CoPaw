# 默认 LLM 模型管理实现计划

## 1. 重组默认 LLM 区域

- 将 `ModelsSection` 从仅分发按钮改为远程可用模型的分组候选模型选择器。
- 从 Provider 数据中过滤本地、未配置连接或无模型项，并合并 `models` 与 `extra_models`。
- 当前值显示供应商和模型名称；无候选或当前值失效时渲染对应空/异常状态。
- 使用租户级 `setActiveLlm` 立即激活，成功仅更新选中状态，刷新失败不回滚已成功写入。

## 2. 在默认 LLM 区集中配置与分发

- 复用现有模型运行配置表单能力，在默认 LLM 区通过“配置”按钮打开当前激活模型详情弹窗。
- 配置保存成功后关闭弹窗、刷新模型数据并提供明确成功反馈；失败保留原状态并显示错误。
- 将激活模型分发按钮放在同一区域，复用现有租户选择和覆盖语义。
- 当前激活模型不是可用远程模型时禁用配置与分发。

## 3. 收敛 Provider 卡片职责

- 从 `RemoteProviderCard` 移除打开模型激活/运行配置的入口。
- 保留模型目录维护入口及 Provider 连接配置入口。
- 调整 `RemoteModelManageModal`：移除模型条目的即时激活和运行配置按钮，仅保留发现、添加、删除、连接测试、多模态探测。
- 清理因入口移动产生的无用激活状态、配置状态和样式。

## 4. 测试与验证

- 为默认 LLM 选择器增加远程候选过滤、分组标签、即时激活成功/失败、当前值失效和本地模型隐藏测试。
- 为默认 LLM 配置入口增加打开当前模型配置和保存刷新测试。
- 更新 Provider 模型管理弹窗测试，验证不再渲染激活与配置操作，同时保留目录维护操作。
- 运行模型管理与聊天模型选择相关测试、ESLint、Prettier、`git diff --check` 和 GitNexus `detect-changes`。
