# 模型管理默认 LLM 交互设计

## 目标

将模型激活、当前模型配置和激活模型分发集中到“默认 LLM”区域，使管理员无需进入某个模型提供商卡片寻找激活入口。Provider 卡片只承担模型目录维护。

## 交互边界

### 默认 LLM 管理区

- 展示按供应商分组、可搜索的远程模型选择器。
- 候选模型必须来自连接已配置且模型目录非空的远程 Provider。
- 选项展示模型名称和模型 ID；当前值展示为“供应商 · 模型名称”。
- 选择模型后立即持久化为当前租户活跃模型，并刷新当前模型摘要。
- 配置操作只针对当前活跃模型，打开模型详情弹窗编辑生成参数与能力配置。
- 分发操作只复制当前活跃模型及其配置到所选目标租户，并覆盖目标租户已有的对应配置。
- 分发不复制整个 Provider，也不复制模型目录。

### Provider 卡片

Provider 卡片中的模型入口只提供模型目录维护：发现、添加、删除、连接测试和多模态探测。

Provider 卡片不提供模型激活或模型运行配置入口，避免与默认 LLM 管理区形成重复工作流。

## 状态与反馈

- 激活成功不弹出成功提示，通过选择器选中态和当前摘要更新反馈。
- 配置保存提供明确的保存成功反馈，并更新默认 LLM 摘要。
- 分发提交保留异步任务已提交提示。
- 激活、配置或分发失败时显示错误，不保留未提交的 UI 状态。
- 刷新失败不否定已经成功的激活或配置写入；界面保留最后一次成功状态并允许后续刷新。

## 空状态与异常状态

- 没有可用远程模型时，默认 LLM 区显示空状态，选择、配置和分发控件不可用。
- 若服务端当前活跃模型是本地模型或已不在候选目录中，不自动改写服务端状态；显示当前值不可用，并要求管理员主动选择远程模型。
- 本地 Provider 和本地模型不进入默认 LLM 候选，也不在管理端展示为可操作项。

## 数据语义

- 激活模型是租户级共享状态，管理端和聊天面板读写同一活跃模型。
- 模型配置绑定到 Provider 下的模型 ID，在该租户所有调用入口生效。
- 激活模型分发复制被激活模型对应的配置；供应商全量分发继续作为独立能力保留。

## 验收标准

1. 管理员可在默认 LLM 区完成远程模型选择、配置和激活模型分发。
2. Provider 卡片中不存在激活或模型配置入口，但目录维护能力不受影响。
3. 本地、未配置或无模型 Provider 不会出现在模型选择器中。
4. 选择、配置和分发的成功/失败反馈符合上述规则。
5. 当前活跃模型不可用时不会被页面自动替换。
