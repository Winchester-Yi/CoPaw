# 聊天历史触顶加载优化方案

状态：已实施并完成针对性验证；验证记录见文末。

## 目标与范围

用户连续向上阅读，首次到达当前顶部即可推进历史，不要求先向下离开 240px 区域。
保持阅读锚点稳定、同一会话最多一个历史推进任务、跨会话结果隔离、失败可重试和终止提示。
初始本地显示 10 张历史卡片、本地每批 10 张、归档每页 limit=20、预加载距离 240px 保持不变。
本次修改范围为 Console 的历史加载协调、对应测试和 OpenSpec，不改后端接口。

## 方案选择

| 方案 | 优点 | 问题 | 选择 |
|---|---|---|---|
| 调整距离或延时清除区域锁 | 改动小 | 仍依赖时序；可能反复请求 | 不采用 |
| 基于当前位置、数据进度和布局完成状态协调加载 | 可复用当前 Hook、分页与锚点逻辑 | 需明确重新检查和停止规则 | 推荐 |
| 替换为虚拟列表及可见范围分页 | 可兼顾大量消息渲染性能 | 动态卡片高度和锚点迁移范围大 | 本次不采用 |

## 核心规则

用“当前位置满足条件且能够推进历史”决定是否加载，取消“必须观察到离开区域才能再加载”的规则。
保留请求锁；防止重复执行的依据改为会话代次、当前本地窗口或归档游标、进行中的操作。
进度标识只是用来识别操作和验证推进，不能永久记录失败游标导致同游标重试失效。

历史推进过程分为：检查位置 → 选取本地批次或归档页 → 提交数据 → 恢复阅读锚点 → 下一帧重新检查。
任务锁覆盖整个过程，不能在 Promise 返回但 React 尚未提交布局时提前释放。

## 触发与重新检查

- 初次挂载只定位到最新消息，不因处于预加载区而自动拉取全部历史。
- 用户向上滚动进入 240px 区域时启动推进过程，后续到顶不依赖区域离开标记。
- 本地批次提交、归档插入并完成锚点恢复后，主动检查最新几何信息。
- 用户退出预加载区、切换会话、进入 error/exhausted 时停止自动补取。
- 若用户在请求期间转而向下阅读，不因请求完成而无条件接着补取；以最新阅读意图及位置决定。
- 程序执行的初始化定位和锚点恢复不作为新的用户加载意图，也不重置补取预算。
- 滚动监听保持 passive；进行中的任务合并重复触发，布局后的位置检查通过 requestAnimationFrame 调度。
- 不再依赖容器 ResizeObserver 检测内容增长；每步完成后跨两帧检查最新布局与锚点恢复结果。
- 滚动 DOM 节点通过实际 ref 生命周期绑定和解绑，避免依赖消息数量推断节点是否重新挂载。

## 本地历史与归档衔接

`advanceHistory` 每一步仍优先展开本地历史，全部本地历史显示后才请求归档。
但本地分支 return 只表示这一步结束，不表示本次向上阅读需求结束。
完成渲染和锚点恢复后，若仍在预加载区且存在阅读需求，则允许下一步进入归档。
如果新增本地内容已经把用户推离预加载区，就停止并等待用户继续向上阅读。

例如本地有 11 张卡片：先展开第 11 张；布局稳定后，如果距顶部仍不超过 240px，
同一轮协调流程可请求归档，不要求用户下滚再上滚。

## 有界补取与兜底

一次自动补齐过程最多推进 3 步，本地批次和归档页都计入，采用模块级常量。
该上限已验证可阻止空页连续取完历史；它是交互预算，不是吞吐量测量结论。
已有过程中的滚动事件只更新位置与阅读意图，不叠加启动多个过程。

达到上限后回到可交互 idle，用户下一次向上滚动或点击“加载更早消息”可继续。
顶部在还有历史且 idle 时提供该按钮，覆盖短列表无法产生真实 scroll、自动补齐到达上限等情况。
不得停在空白状态又要求用户必须先下滚。

以下条件立即终止自动补取：

- `has_more=false`：展示结束提示。
- 请求失败：保留当前消息和游标，展示失败及重试，禁止自动无限重试。
- 归档声称还有更多但 next_cursor 为空或与请求游标相同：标记无法推进，展示失败及重试。
- 会话或历史代次变更：忽略旧响应和旧布局回调，不得解除新任务的锁。

响应没有新增可见卡片但游标确实推进时，可在预算内继续。
用户主动重试允许请求同一游标，但仍受单任务锁控制。

## 锚点与异步布局

复用现有消息 ID 与相对视口偏移锚点；保持禁用浏览器自动锚定，避免双重补偿。
layout effect 立即恢复锚点，并覆盖后续两帧 Markdown 布局；协调器检查 pending 事务已结束后才推进。
程序滚动坐标标记独立于 pending 生命周期，覆盖延迟派发的 scroll；真实移动取消旧恢复。
会话切换时取消待执行帧并校验 generation。
不为每张历史卡片添加独立观察器，不扩展为一次完整的消息渲染重构。
对滚动区域的内容盒子增加单个 ResizeObserver，补偿 Markdown 等迟到布局。
只有当前 pending 或阅读锚点仍属于本次内容代次时才恢复；真实移动使旧锚点失效，
内容更新、节点替换和卸载时清理观察器，避免旧回调修改用户阅读位置。

## 文件职责与实施顺序

1. `Bubble/hooks/useHistoryPreload.ts`：去除区域离开作为强制门槛，处理位置检查、单次推进协调与有界补取。
2. `Chat/MessageList/index.tsx`：提供本地/归档进度、执行推进、布局完成通知及代次校验；保持现有数据去重。
3. `Chat/MessageList/HistoryLoadStatus.tsx`：idle 且还有历史时显示继续加载入口，保留加载、失败、重试及结束语义。
4. 对应 Hook/MessageList/HistoryLoadStatus 测试：先覆盖可复现失败路径，再调整实现。
5. `openspec/specs/chat-message-history-loading/spec.md`：将“离开再进入”修改为“向上阅读时当前位置满足条件即可推进；自动补取有界”。

具体符号修改前按仓库规则执行 GitNexus impact，并报告调用范围；提交前执行 detect_changes。
不进行与该问题无关的组件拆分或样式调整。

## 验收矩阵

| 场景 | 预期 |
|---|---|
| 首次打开已有会话 | 显示最新历史窗口，不自动遍历历史 |
| 第一次正常上滑到顶 | 展开本地历史或请求归档，无需先下滚 |
| 本地 11/25 张历史卡片 | 分批展开，最后一批后的归档衔接符合最新位置 |
| 插入内容后下一个事件直接到新顶部 | 不受旧区域锁阻止 |
| 最后一个本地批次很短 | 顶部仍接近时可自动衔接归档 |
| 归档无新增可见消息但游标前进 | 预算内继续，不死循环 |
| 游标不前进且 has_more=true | 停止自动取页，提供明确失败与重试 |
| 慢请求期间反复滚动 | 同一会话只有一个进行中的推进任务 |
| 请求期间向下阅读 | 返回后不无条件继续拉页 |
| 加载失败与主动重试 | 消息保留，同游标重试，错误不自动连发 |
| 短列表无可滚动空间或预算耗尽 | 继续加载按钮可操作，无需制造滚动 |
| 切换会话及同消息数量重挂载 | 监听绑定当前节点，旧响应与旧帧不污染新会话 |
| 图片/Markdown 高度变化及实时输出 | 阅读锚点稳定，用户不被意外拉回底部 |
| 普通与 content-only 模式 | 分页行为一致，原权限边界保持 |

验证分为动态 DOM 几何的单元/组件测试和使用真实 Bubble.List 的浏览器测试。
不能只使用固定 scrollHeight 的模拟组件证明问题修复。


## 实施结果与验证（2026-10-19）

已移除强制离开预加载区的门槛。本地展开和归档请求共用推进锁，最多推进三步，
每步等待布局与锚点事务结束；向下阅读、错误、无进度和历史结束均停止。
重试也经过同一协调器。列表实际 DOM ref 生命周期负责监听绑定；会话与压缩代次隔离旧响应和旧帧。
顶部新增“加载更早消息”兜底，并检查归档游标必须前进。

另修正反向列表的底部判断：负 scrollTop 表示正在阅读历史，不能一律判为已到底部。
保存可见消息 ID 与视口偏移，实时消息更新后恢复阅读位置。
真实浏览器发现 Markdown 的高度变化可能晚于第二帧，因此保留两帧初始恢复和明确的事务完成检查，
并观察内容盒子尺寸变化；仅在当前阅读锚点有效时补偿迟到布局，真实移动取消旧锚点。

验证结果：

- Bubble、MessageList、sessionApi 相关 9 个测试文件、103 项测试通过。
- 修改涉及的 8 个 TS/TSX 文件定向 ESLint 通过，生产构建（含 TypeScript）通过。
- 7 个文件 Prettier 检查通过；BubbleList.tsx 的现存解构格式不符合 Prettier，HEAD 基线亦相同，保持未改。
- 浏览器使用真实 MessageList、Bubble.List、反向布局与 Markdown，API 使用可控模拟响应。
- 首次挂载请求 0 次；11 张本地历史首次向上滚动展开最后一张，并衔接 2 页归档，无下滚动作。
- 短列表空页每轮最多 3 页，手动继续后共 6 页并显示结束提示。
- 25 张本地历史分批展开、普通模式相同消息数量重挂载及会话切换验证通过。
- 实时新增消息后，首个可见锚点位置保持在 2px 容差内，且恢复滚动不产生额外归档请求。

限制：浏览器验证覆盖真实前端组件与可控 API，不代表已在部署环境完成网络与后端端到端验收。
构建保留仓库已有的大 chunk 提示；本次不扩大为打包拆分重构。
