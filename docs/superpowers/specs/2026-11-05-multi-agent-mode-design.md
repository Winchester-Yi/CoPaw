# 多智能体模式设计

## 目标与语义

在聊天输入区的模式菜单增加“多智能体”开关。开启后，当前会话的后续用户请求显式表达子代理委派意图，效果与该请求的用户文本包含 `SubAgent` 或“子智能体”等现有关键词一致。主 Agent 可以选择是否委派；开关不强制启动子代理，不改变工具权限、审批或专家自主发现配置。

模式按 Chat 保存，刷新或切回时恢复；新建和重置 Chat 默认关闭。切换只影响之后提交的请求，不中断已经提交的回合或运行中的子代理。开关关闭时，关键词仍按现有规则单次生效，不自动开启模式。

## 交互与互斥

模式菜单提供开关，开启时输入区显示可关闭的“多智能体”状态标识。它可与计划模式、目标模式同时开启；计划模式继续限制只读委派，Goal 保留自身授权规则。

多智能体与任何显式专家选择互斥：开启多智能体时清除普通专家选择或解除专家主执行绑定；选择专家时关闭多智能体。界面提示因此发生的切换。持久化专家绑定与模式的切换必须作为一个整体提交，失败或版本冲突时保留原来的持久状态和界面状态并提示重试；不得依赖两个独立写入加客户端补偿实现原子性。普通专家选择是本地状态时，也仅在持久化成功后更新。跨页并发与旧页面提交须遵守现有专家绑定版本检查；切换期间禁止冲突操作。原有非终态 Goal 对专家和计划模式的限制继续适用。

## 请求与持久化

会话元数据保存多智能体模式状态，缺省为关闭，并遵循现有租户、用户、Chat 边界。服务端应提供一次受并发控制的状态变更，使模式与持久专家绑定的互斥在存储层成立；专家选择的反向操作也必须遵守同一约束。保留其他会话元数据及专家绑定版本，避免陈旧页面覆盖新状态。新建临时会话、真实 Chat ID 解析、刷新、切换及重置均须覆盖。

普通用户消息在 `/console/chat` 请求中传递顶层 `enable_subagents`，由现有 `has_subagent_intent` 与关键词路径汇合，不修改用户消息。提交时捕获模式状态；已有请求、流重连和自动续跑不因之后的开关变化重新授权。实施时验证请求模型和传输层确实保留该字段，不能仅依据前端请求体推断后端已接收。

当前 Goal 的普通输入可能直接走 steering 接口，必须同样传递提交时的标志。Goal 草拟、确认、steering 和恢复沿用现有真实用户意图及 Goal 持久授权机制：只打开开关不授权；开启后提交真实用户消息可授权该 Goal，关闭开关不撤销已经建立的授权，也不向其他 Goal 或普通聊天扩散。系统生成的恢复消息和自动轮次不得仅因开关状态变化而创造新授权。

Goal 状态面板根据实际 Goal 快照显示委派授权状态。关闭开关时，若当前 Goal 已获授权，提示关闭不会撤销该授权；状态读取失败时不得声称授权已撤销。Goal 状态变化后刷新快照，避免把开关状态当作 Goal 授权状态。

## 验证

- 测试模式默认值、保存恢复、会话隔离、新建和重置、临时 ID 切换及保存失败。
- 测试普通聊天和 Goal steering 的真实请求字段，以及文本关键词与显式标志进入同一工具注入路径；关闭模式后关键词仍有效，不含关键词时不得因此获得新建权限。
- 测试计划模式组合下的既有只读策略，Goal 草拟、确认、steering、自动轮次及恢复的授权边界；打开开关但未发消息不授予 Goal 权限，关闭不撤销已有权限。
- 测试两种专家选择的双向互斥、存储失败、版本冲突、跨页面并发、会话切换与旧请求提交；确认失败不会出现部分持久切换或丢失用户草稿。
- 测试切换不取消进行中的回合或子代理，Goal 面板和关闭提示反映实际授权，输入区状态可通过键盘和辅助技术操作。
- 运行相关 Console 测试、类型检查和后端定向测试，并按项目规范检查普通及 `hideMenu=true` 场景；在真实 Chromium 108/对应 360 内核和当前浏览器验证布局、滚动与核心交互。环境不可用时明确记录未验证项。

## 范围外

不改变子代理调度、专家发现开关、权限策略、Goal 授权撤销机制，或为子代理引入新的执行方式。历史子代理管理仍按现有 Chat 归属规则运行。
