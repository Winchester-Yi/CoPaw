# SWE/Monitor Token 核心诊断 B：完整设计稿

日期：2026-10-12。状态：完整设计已获用户确认，进入实施计划阶段；B-Q1 至 B-Q16 及后续技术设计作为 B 开发依据，尚未开始 B 生产代码实施。

依据：[MVP v1.0](../../../Agent_Token_效率诊断平台_MVP_方案设计_v1.0.md)、[观测底座 A](2026-10-12-token-diagnostics-observation-foundation-design.md)。

## 继承边界

- 延续 SWE/Monitor 增量开发、Token 独立记账和租户/来源隔离；Task 仍对应一次根请求执行。
- 保留现有五规则的身份及历史语义；八条新规则分别定义版本、证据条件和降级状态。
- 业务优先、有界非阻塞采集；数据不足不能显示为未命中或零消耗。
- 不默认持久化原始 Prompt、工具参数/结果或 Token 序列；数据库继续使用类型化列及必要关系表。
- 专门逐请求 Usage 核对继续暂缓。人工确认/误报反馈、实验对比与策略知识库的完整闭环均留在 C。
- B 设计覆盖全局看板、执行诊断和优化问题清单，并同步明确各页面指标的证据来源。

## B-Q1：前缀分析深度（已确认 A）

用户选择消息／文本级近似。本轮目标是客户端可取得的有序输入表示之间的前缀相似度、首差条目及比较覆盖范围，不将其命名为精确 Token 前缀、服务端 KV 可复用量或实际缓存命中率。

- A 的整条内容 HMAC 只能判断整条表示是否相同，不能还原条目内部的最长公共前缀；B 需要新增有序前缀证据采集。
- 文本长度及 UTF-8 密度估算须明确单位与估算器版本，不能用估算长度冒充 Provider 报告的输入 Token。
- 模型、表示格式、采集阶段、密钥版本及时间窗口的比较条件见 B-Q3、B-Q4 和下文技术设计；不得跨 source/tenant 比较。
- 最终服务端 Tokenizer、模板、缓存块和服务池未知时，准确缓存机会相关字段保持不可用。
- 新证据仅覆盖启用 B 采集后的请求；不承诺从 A 的整条 HMAC 回补文本前缀。

## 设计阅读顺序

跨轮片段身份及出现实例 → 有序前缀表示与比较条件 → 上下文操作与工具证据 → 八规则及统计分母 → 三页面交互 → 存储/API 与验收。

下面保留逐项确认记录；技术设计、存储/API 及验收在末尾汇总。整体评审通过后再生成实施计划。

## B-Q2：跨轮片段身份（已确认 A）

片段追踪采用“来源身份优先、内容指纹辅助”的双层口径：

- 有可靠来源时，优先使用消息/工具操作/受控来源对象 ID；同一来源的不同内容版本保留为同一逻辑来源的不同出现事实。
- 每次出现仍保存 occurrence 记录、顺序、估算规模、采集阶段和 HMAC；HMAC 用于核对内容变化，不替代来源身份。
- 没有可靠来源时，不生成跨轮稳定 ID；只能报告当前比较窗口内的内容重复，并将生命周期、首次引入和持续携带状态标记为 unknown。
- 相同内容但不同工具操作、租户、来源范围或安全域不得自动合并；跨 source/tenant 的 HMAC 和片段比较禁止进行。
- 原始内容不落库；页面展示来源类别、受控来源引用、版本和完整性状态，不展示 Prompt/工具结果正文。

## B-Q3：前缀历史窗口（已确认 A）

前缀相似度采用最近 24 小时的历史窗口。候选必须在当前请求开始前已完成，不能使用正在执行或未来请求的数据。页面同时展示窗口长度、符合比较条件的请求数和缺失/排除情况。

该窗口用于客户端文本结构比较，不代表模型服务的实际缓存 TTL、Prefill 驻留时间或可命中范围。分组条件与有界候选检索分别见 B-Q4、B-Q11。

## B-Q4：前缀比较范围（已确认 A）

允许比较同一 Agent 的不同 Token Diagnostic Task，目的是观察系统提示、工具 Schema 等固定内容在不同任务中的前缀稳定性。

- 必须位于相同 source/tenant、Agent、Provider/模型以及兼容的客户端表示格式/版本、采集阶段和指纹密钥版本范围内。
- 沿用 B-Q3 的 24 小时和已完成请求条件；媒体、截断输入、缺少身份或指纹等情况分别列为不适用或数据不足。
- 不同 Task 的前缀相似不建立片段生命周期关联；生命周期统计继续按实际执行分支、可靠来源身份和出现事实进行。
- 跨 Agent、跨模型、跨租户或跨来源的请求不参与本轮前缀比较。

## B-Q5：R08 同类模型用量异常（已确认 A）

保留 R08 的规则身份与评估入口，但当前没有可靠的任务类型、复杂度、业务质量及可比组时，明确显示“证据不足”并列出缺失条件。

- 看板仍可展示已观测 Agent/模型用量分布、样本量和完整性，不能将这些分布直接作为同类业务任务异常结论。
- 执行 completed 不代表业务成功或质量达标；不通过 Prompt 内容、Token 数或模型名称猜测任务复杂度/质量。
- 本轮不增加业务侧任务分类与质量采集约定；可靠比较组及至少 30 个符合条件样本具备后，才允许执行 R08 的统计判断。
- 未接入可靠价格与计费语义时不计算成本异常，不用 Token 估算值冒充实际费用。

## B-Q6：工具安全属性声明（已确认暂不增加）

本轮不增加工具注册声明机制，也不按工具名字、Prompt 或相同返回内容推断只读、幂等或可缓存性。A 已有 unknown/false/null 口径继续沿用。

- 可以展示相同工具、参数指纹和结果指纹的重复调用事实，并保留各次调用的证据引用。
- 缺少只读/副作用、幂等性、可缓存性及数据版本等可靠证据时，R04 的安全复用判断显示“证据不足”，不输出已确认可缓存、可跳过或预计节省量。
- 未取得进展信号时，R05 只能报告可疑重复，不能把没有采集进展当成证明没有进展。
- 既有五规则及 API 语义保持不变；新增规则用自己的身份与版本表达上述降级，不借用旧 ID 改写历史结论。

## B-Q7：可视设计形式（已确认 A）

采用浏览器交互线框与设计文档共同确认页面。页面结构已在 B-Q8 确认；完整 B 实施设计仍在收敛。

线框：[三页面交互预览 v3](../mockups/2026-10-12-token-diagnostics-b-v3.html)。全部数值为模拟数据，未接入业务 API；非样例 Task、分支、时间与模型筛选仅展示交互位置。视觉遵循 Console 的白色画布、紧凑中文管理界面及蓝色强调规范。

### B-Q8：页面结构（已确认 A：三个独立页面）

采用三个独立页面，分别服务总体观测、单次执行查证和跨执行问题整理。每页拥有独立路由，可携带筛选和证据定位状态；从问题清单进入执行后，返回时保留原问题筛选。未采用单页三标签方案，避免将不同层级的筛选和定位状态集中在同一页面。

| 页面 | 核心内容 | 下钻路径 |
| --- | --- | --- |
| 全局 Token 看板 | 当前来源及租户已知用量、已记录 Task、Usage 完整率、Agent 用量分布、规则评估覆盖与前缀比较覆盖 | Task → 执行诊断；规则 → 问题清单 |
| Agent 执行诊断 | Task 内独立分支、调用顺序、准备输入构成、来源出现事实、前缀首差与上下文操作证据 | 问题实例定位到 Task / Branch / Call / Context；执行 → 关联问题 |
| 优化问题清单 | 同范围规则候选聚合、独立命中证据、建议前提和证据不足的评估 | 问题组 → 命中实例 → 执行证据 |

现有 Token 记录与诊断入口以及五条旧规则继续保留。新页面具体路由及只读接口见下文存储/API 设计。

### 页面证据边界

- 总 Token 仅汇总已知 Provider 用量；部分报告、未知与采集完整性单列。Task 用量完整与输入明细捕获完整是不同状态。已记录任务/调用数不声称覆盖所有实际执行。
- Usage 完整率在线框中为完整报告调用数 / 已记录调用数，同时显示分子、分母。该比率不是专门逐请求 Usage 核对结果；核对工作仍暂缓。
- Agent 用量排序不作为效率或质量排名；Task 用量分位数仅使用符合完整性条件的样本，显示样本量。
- 前缀统计显示可比较请求、有历史候选、无候选和排除原因。线框示例为 116 个可比较请求，其中 89 个有候选、27 个无候选；124 个排除请求按互斥主原因拆分。共同前缀比例按 B-Q15 的字节加权口径计算，参与范围进一步受检索成功及候选未超限约束；不用线框的 32.6% 固化算法。
- Provider 输入与准备输入估算分开展示，不将差额按比例强行归因。调用选择应更新该调用的构成及证据；分支汇总明确标注作用范围。线框前缀面板固定标注为调用 2 样例，正式页面须按定位调用加载证据。
- 同一来源的重复出现展示涉及估算量，不声称无价值或可节省。无可靠来源身份的条目生命周期保持未知。工具安全证据缺失、业务质量未知及上下文变换证据缺失都直接可见。
- 问题组的命中次数、涉及 Task 数和证据签名分别展示；聚合不代表共同根因已确认。候选涉及规模可能重叠，不汇总为预计节省量。规则与阈值版本、实际观察值及证据引用在命中实例保留。
- B 不放确认/误报反馈按钮；人工反馈、实验对比及完整策略知识库均留在 C。

### 本轮线框检查

已在浏览器检查看板渲染、三页切换、调用选择与规则详情切换；调用 3 的输出保持未知，固定内容占比随调用估算分母更新。线框只验证设计表达，不等于 Console 生产页面开发或真实数据验证。

## B-Q9：规则门槛策略（已确认 A）

沿用 MVP 的启动阈值，但先检查每条规则所需证据与适用性，再执行阈值判断。规则定义与阈值配置分别版本化，命中保存当时阈值快照；后续校准不改写历史结论。本轮不增加面向业务用户的阈值编辑页面。

- 事实与诊断分开：重复、增长或结构变化可以展示；满足门槛才形成优化候选，候选不意味着浪费或允许自动整改。
- 证据齐全且满足条件：形成候选；证据齐全且不满足条件：已评估未命中；必要证据缺失：证据不足；明确超出规则适用范围：不适用；尚未执行评估：待评估。
- 未知、采集失败或队列丢失不计为未命中。连续性必须在同一执行分支内确认；已知存在调用缺口时，不能跳过缺口拼出“连续三轮”。
- Token 规模门槛沿用 MVP 启动值的规则，文本估算必须携带估算方法及版本，界面显示近似单位。Provider 报告用量与文本估算不能混成同一增长序列或同一比例的分子、分母。
- R04 的安全证据缺失、R05 的进展采集缺失及 R08 的业务比较组缺失继续按已确认边界降级。R06 的文本近似单位和门槛将单独定义，不直接把 MVP 的精确 Token 前缀门槛移植成字节门槛。

未采用仅展示事实与分布、暂不生成阈值候选的方案；B 首版需提供有证据及门槛依据的优化候选。

## B-Q10：文本前缀证据粒度（已确认 A）

保存有序条目元数据与文本分块的链式 HMAC，既定位首个不同条目，也估计该条目内部已匹配的文本范围。仅在客户端已有输入表示上进行比较；不持久化原文，不增加 Token 序列采集。

- 比较表示保留角色、条目边界及实际数组顺序；不通过去空白、重排工具或消息来消除实际差异。表示定义独立版本化。
- 分块指纹包含此前的序列状态和边界信息，从序列起点连续匹配；后面的相同内容不能越过首次差异计入共同前缀。条目身份与内容指纹继续分开。
- 输出已确认匹配的客户端文本字节范围及首差条目；分块内部的差异位置只能报告区间，不伪造精确字符或 Token 偏移。块大小、采集上限及候选检索上限在有界采集设计中固定。
- 发生截断、预算耗尽、媒体或指纹缺失时，保留原因及捕获范围；不得把局部指纹当作完整输入参加正常比例及规则判断。比较仍受已确认的 24 小时、历史完成时序及隔离组约束。

未采用仅保存整条消息/Schema 有序指纹的方案，因为它无法估计首差条目内部的共同前缀长度。

## B-Q11：历史候选检索范围（已确认 A）

每个请求只比较已确认隔离组及 24 小时窗口内最近 100 个符合条件、且在当前请求开始前已完成的历史请求。按完成时间降序、稳定请求标识作为同时间排序条件，确保检索可重现。候选选取策略及其上限独立版本化，分析异步执行，不阻塞业务调用。

- 结果称为“已比较候选中的最大共同文本前缀”，不声称是整个窗口的最佳匹配。记录实际比较数、候选上限、选取策略版本及是否超过上限；窗口候选总数无法可靠取得时保持未知，不把上限当成总数。
- 无历史候选、检索未完成、检索失败、候选截断和输入证据不完整分别展示。无候选不参与共同前缀比例，未完成或失败不视为零匹配。
- 候选超过上限时，已比较结果仍可展示，但 R06 不能仅凭这个局部结果断言整个窗口前缀比例低或没有匹配机会。若 R06 的低比例判定需要完整候选覆盖，缺少覆盖时输出证据不足。
- 单个请求匹配到的完整块长度仍是客户端共同文本前缀的保守下界；字节分块误差与候选检索截断是两个独立的限制，需要分别标注。

未采用比较窗口内全部兼容历史请求的方案，以限制高流量 Agent 的检索及计算成本。

## B-Q12：上下文操作前后证据（已确认 A）

在运行时实际发生上下文操作的边界采集前后快照元数据，并通过 operation_id 关联；不增加压缩、清理或截断业务行为。快照只包含来源、顺序、指纹、规模估算及完整性，不保存原文。

- 操作前后 Context 为独立快照，角色标记为操作前/后；它们不冒充已发送模型的准备输入，也不进入模型调用用量及前缀请求统计。
- 只有同一操作、同一表示及估算方法版本、覆盖完整且状态成功的前后证据，才能展示该操作的上下文规模净变化。操作之间加入新消息或发生其他变换时，不用下一次模型调用代替操作后快照。
- 移除、替换及新建片段按可靠来源引用或操作产生的关联记录展示；仅凭某片段未在截断快照中出现，不认定其已被移除。无法取得替换关系时显示未知，不猜测摘要对应来源。
- 前后规模变化只表达客户端上下文变化，不称为 Provider 实际 Token 节省或质量无损。摘要模型调用独立记账，能关联时保留引用；不能关联时明确缺口。
- 操作失败、跳过、前后仅一侧捕获、预算耗尽及不支持的操作分别保留状态；缺少快照不影响业务执行，也不阻碍基础统计。

未采用仅保留上下文操作发生及完成事实的方案；B 需要支持有证据的前后变化展示。

## B-Q13：问题清单聚合语义（已确认 A）

按兼容范围及可靠证据签名保守聚合，名称为“问题组”，不将其命名为已确认共同根因。每次规则命中保留独立实例和证据引用，问题组仅组织查阅及统计。

- 聚合范围至少包含 source/tenant、Agent、Provider/模型、规则定义版本及阈值配置版本；不同范围或版本不自动合并。
- 证据签名按规则定义，使用可重复的结构位置、受控配置版本、工具身份或其他可靠证据类别。跨 Task 聚合键不使用仅在单次执行中有效的消息或工具操作 ID；这些引用仍保留在命中实例，用于定位而不是假定跨 Task 来源相同。
- 不仅凭同一规则命中、相似 Token 数或同样内容合并不同来源。必要结构证据或身份缺失时保留单独实例，并标注无法可靠聚合；不把所有 unknown 放进一个问题组。
- 问题组展示当前筛选范围内命中次数、不同 Task 数、首次/最近命中时间及代表实例。代表实例用于导航，不代表全部命中具有相同规模；涉及估算量不能简单相加为节省量。
- 同一输入及分析版本的评估重试不能重复新增命中。改变输入证据、规则或阈值后的评估保留新版本关系，不能覆盖原评估证据；默认统计口径须区分历史评估与当前有效评估。
- 证据不足、不适用及待评估单列在评估覆盖区域，不能混入命中次数或算作已确认问题。人工确认/误报反馈留在 C。

## B-Q15：看板共同文本前缀比例（已确认 A）

采用文本字节加权：Σ每请求最佳候选的已确认共同文本字节 / Σ同一批请求的完整客户端文本字节。分子、分母使用同一表示版本与单位，先在各兼容组内匹配，再按页面筛选范围汇总匹配结果；不能为了汇总而跨组找候选。

- 主指标仅包含输入完整、具有历史候选、检索成功且候选未超限的非空文本请求。无候选、候选超限、输入截断、媒体、检索失败及待处理请求分别列出数量，不按零匹配混入分母。

- 分块匹配产生的已确认长度为保守下界，指标标注“共同文本前缀比例（保守估计）”，不称为缓存命中率。候选超限的结果仅在详情及单独的受限统计中展示。
- 指标同时显示参与请求数、分子与分母字节数及各类缺口；参与请求数为零时显示不可用，不显示 0%。页面模拟值不会作为算法或验收期望值。
- R06 不直接用这个保守下界低于阈值来认定前缀不足；正式规则需结合块内差异区间的上界与完整候选覆盖，无法判定则证据不足。

## B-Q16：R06 文本近似判定（已确认 A）

首版使用固定启动门槛形成“文本前缀稳定性优化候选”，不增加 Agent 历史基线下降判定。该规则以当前请求为评估对象，不直接从跨请求看板汇总比例推导单次命中。

需要同时具备以下条件：

1. 当前请求及至少两个历史请求具有完整兼容文本证据；历史请求均符合当前请求开始前已完成、24 小时窗口及隔离组条件，候选检索未超限且已成功完成。
2. 有受控结构来源或配置身份支持的静态内容在这三个请求中保持相同内容版本，其文本估算规模合计至少 2000 estimated tokens；使用同一估算方法版本。该门槛为近似规模，不是 2000 字节或真实服务端 Token。只有同样文本、缺少静态来源证据时，不自动满足此条件。
3. 当前请求相对所有符合条件候选的最大共同文本前缀比例，其可证明上界仍小于 20%。分块匹配保留下界及首差块区间；对每个候选取安全上界，再取所有候选中的最大上界。无法构造可靠上界时保持证据不足。

上下界区间跨过 20% 时不能形成低比例候选；候选超限时，即使已比较结果很低，也不能据此判定整个窗口缺少匹配。完整证据已经证明门槛不满足时为已评估未命中，必要证据缺失时为证据不足，无历史样本等明确适用性条件不满足时为不适用。

输出当前请求、历史候选范围、静态内容估算及方法版本、共同文本比例区间和首差证据。建议检查静态内容顺序及动态插入位置，并要求验证指令遵循；不输出实际缓存未命中、可节省 Token 或可自动调整。

未采用同时增加相对 Agent 历史基线下降的方案，本轮不建立额外基线学习与漂移判定机制。

## 技术设计：版本、表示与有界采集

本节为整体评审稿的默认技术方案，继承前述已确认决策。

### 版本与职责

- A 事件契约 `1.0` 继续可读；B 新增证据使用 `1.1` 的增量契约，旧字段语义不变。独立记录事件契约、输入表示、估算器、指纹密钥、规则定义和阈值配置版本。
- 八规则新增身份为 `context_growth`、`segment_carryover`、`tool_context_volume`、`safe_tool_repeat`、`suspected_loop`、`text_prefix_stability`、`static_context_volume`、`cohort_usage_outlier`，页面分别显示 R01–R08；初始规则定义版本与阈值配置版本均为 1。不复用现有五规则的 ID，也不改写其结果。
- A 记录缺少 B 指纹、快照或结构身份时显示缺少相应证据，不伪造回填。B 写入器认识 1.0/1.1，遇到不支持的契约显式拒绝并记录缺口；部署先更新存储和 Monitor，再启用 SWE 的 B 采集。
- SWE 的采集异常只影响观测，Monitor 的分析失败只影响诊断；三个页面均从持久化的观测和分析投影读取，不在读取时生成业务侧采集或调用 Provider。

### 客户端比较表示

比较表示使用 `client-ordered-text-v1`：先是请求中工具数组的有序 Schema 条目，再是消息数组的有序消息/内容块。这个固定组件顺序只定义客户端诊断表示，不能解释为服务端 Chat Template 的实际顺序。各数组内部保持实际顺序，文本保留空白及 Unicode 原样，不把工具或消息排序后比较。

条目边界、角色、受控块类型及工具名称使用无歧义的类型标记和分隔编码；Schema 对象键采用固定排序的结构序列化，数组仍保持顺序。因此 Schema 键顺序不反映线上的字节序，而结构内容/工具顺序变化仍可识别。序列化策略随表示版本固定，页面明确显示消息级近似。新增或未知内容块类型没有受支持表示时标为不支持，不静默跳过。

指纹输入包含隔离域、密钥版本、表示版本及块序号，使用 HMAC-SHA256 链式摘要。单条目的内容/结构指纹用于按顺序定位首差条目；整段链式块指纹用于估计共同前缀范围。实际身份引用不进入内容相似度摘要，避免不同 Task 的消息 ID 破坏内容比较；身份仍独立保存用于来源与生命周期判断。密钥留在 SWE，Monitor 只比较同版本摘要，不取得密钥或原文。

默认每块 256 字节，包含结构编码；每块保存累计结构序列字节区间及客户端文本字节区间。统计只计文本字节，不将结构标记长度计作正文。相同链式块证明其之前全部编码内容相同；首差块给出保守区间，后面的相同内容不再累计。不同总长度时比较完整的共同块，并处理短尾块与序列终止标记，不能把短序列当成无限延伸的前缀。首差条目由有序条目指纹确定，首差块可能跨条目，不能将块起点冒充首差条目的精确位置。

### 默认预算和超限行为

| 范围 | 默认上限 | 超限结果 |
| --- | --- | --- |
| 每 Context 条目 | 2000，沿用 A | 捕获不完整，保存原因及已捕获范围 |
| 每 Context 前缀编码输入 | 256 KiB，最多 1024 个块 | 前缀证据截断，不参与正常比例及 R06 判定 |
| 每次快照额外采集时间 | 5ms 的协作式时间预算 | 停止进一步捕获，记录预算耗尽；不是业务延迟硬保证 |
| 单条队列记录 | 512 KiB，沿用 A，包含全部元数据 | 拒绝超限记录并计缺口，不让队列失去边界 |
| 进程队列 | 1000 条 / 16 MiB，沿用 A | 非阻塞拒绝、缺口计数，业务继续 |

操作前后每侧独立应用快照预算，并共享进程队列预算。缺侧、时间/大小截断、缺密钥、媒体、不支持内容、队列丢弃分别记录；进程退出或全批写入失败导致缺口也未落库时只能报告完整性未验证，不能承诺缺口零丢失。

### 调用尝试、逻辑轮次与历史到达

用量始终按独立调用尝试计账；R01/R02/R03 的连续轮次按同一分支的逻辑调用排序，重试不凑成三轮。一个逻辑调用的多次尝试若输入表示及 Context 一致，只计一次上下文出现；若其 Context 不一致且没有可靠区分，连续性判断证据不足，仍逐尝试保留事实及用量。

前缀分析按独立请求尝试比较。历史必须有可靠结束时间且早于当前开始时间；当前与历史均不使用运行中或结束时间缺失的记录。每次分析固定一个数据库可见快照边界，只使用该边界已到达的候选，记录候选策略及范围。晚到历史不会悄悄更改已保存结论；当前请求之后因自身证据修订或显式重分析重新评估时，生成新的评估历史。候选覆盖只描述该快照中的已记录请求，不能证明全量业务流量已覆盖。

比较的最佳下界候选与最大上界候选可能不同，分别保存，不把某个候选的上界冒充全部候选的最大上界。候选列表保存每个 Context 的固定修订及上下界结果，以便复查 R06。静态内容的三请求重复证据需独立验证，不能靠前缀下界反推静态来源。

匹配可通过链式块摘要的单调一致性质二分查找首差块，避免将 100 个候选的全部块加载到请求线程；每次后台分析仍受到时间预算约束。所有查找都带 source/tenant 和兼容组条件，不只按 Context ID 查询。

## 八规则执行合同

除 R06 单独定义文本比例外，以下 K 为 1000 Token 或同版本估算 Token，具体依据在每次评估中保存；不得混用两种来源。每次评估先检查适用性及证据完整性，输出 `candidate`、`not_hit`、`insufficient_evidence` 或 `not_applicable`。待执行/分析失败是任务状态，不能转为 `not_hit`。

| 规则 | 首版判断与必要证据 | 限制及降级 |
| --- | --- | --- |
| R01 | 同分支连续至少 3 个逻辑调用严格增长，末次/首次至少 2、净增至少 8K；或可信总上下文窗口压力至少 80% | 增长来源一致，首值为零时比例不可用；总窗口压力需总上下文限制及预留输出。只有输入预算时另显示输入预算占比，不冒充总窗口压力 |

| `swe_token_prefix_candidates` | `(comparison_id, candidate_index)` | 历史 Context/请求/修订、排序依据、每候选上下界及首差引用；最多 100 条，全部带作用域，保留最佳下界/最大上界的不同引用 |
| `swe_token_diagnostic_evaluations` | `evaluation_id`；作用域/分支/对象/规则/阈值/输入修订/分析快照唯一键 | 评估对象及类型、规则版本、阈值版本、输入/历史快照修订、状态、时间、替代评估引用；历史追加，当前指针在同事务更新；同 Step ID 在不同分支具有独立评估身份 |
| `swe_token_diagnostic_findings` | `finding_id`；`evaluation_id + instance_key` 唯一 | 评估引用、Agent/Provider/model、签名及其版本、可靠聚合标记、定位及建议代码；索引作用域/Agent/规则/签名/时间 |
| `swe_token_diagnostic_values` | `(evaluation_id, value_key)` | 指标名、单位、整数/小数/受控枚举值、上下界及阈值快照；明确值类型，仅对应类型列有值，原文不可写入 |
| `swe_token_diagnostic_gaps` | `(evaluation_id, reason_code)` | 必要证据缺失及限制的受控原因代码；不保存任意异常堆栈/敏感文本 |
| `swe_token_diagnostic_refs` | `(evaluation_id, reference_index)` | Task/branch/Step/Call/Context/occurrence/operation 的类型化证据引用；回查全部验证作用域 |
| `swe_token_diagnostic_heads` | `(source_id, tenant_id, branch_run_id, object_type, object_id, rule_id)` | 当前有效 evaluation 引用、输入修订及规则/阈值版本；通过作用域/分支/对象查找，提交时原子替换指针 |

表中 source/tenant 必须为非空；关联 IDs 不能绕过作用域检查。Context/operation/评估使用有界 ID，指纹使用固定长度十六进制字段，状态与原因用受控 VARCHAR；正文与任意大字段不进入表。金额字段本轮不建立。

单次 Context 及其 occurrences/blocks 原子写入；失败不提交“complete”头部配上半份明细。操作前后可分次到达，关联后才能标记成对完整。A 的 call 仍引用 prepared Context，不引用操作快照；A input_items 保持旧接口投影，B occurrences 保存精细证据，事务中核对重复投影版本。

评估历史追加，当前有效评估指针由 `swe_token_diagnostic_heads` 维护。提交时检查租约、输入修订及候选快照，替代关系和头指针在同事务更新。输入已变化时新评估保留为历史但不成为当前，对象继续待分析。重试复用同一次分析快照标识；同样输入/分析版本/快照重试命中唯一键后幂等处理，显式新分析采用新快照身份。

分支评估仍用现有分支租约；Task 查询摘要按其子分支分别检查修订，不能以修订简单求和证明逐分支追平。一个分支失败或过时，Task 摘要需显示对应状态。八规则各自绑定明确的分支、调用或 Step 对象，跨 Task 的前缀检索不会把分支连续性扩大到整个 Task。

问题组从当前有效 findings 的可靠签名查询聚合，不再建立可漂移的问题组计数表。代表实例选当前筛选范围最近一次，group key 包含规则/阈值/签名版本及兼容范围；无法聚合的实例按自身 finding ID 分组。分析历史与当前统计分开返回。

结构化观测沿用 30 天保留策略；清理只处理 Token 自有表，按对象关系从明细到头分批删除，覆盖全部新增表。活动/近期分支沿用 A 保留保护。原始证据过期后，页面显示证据已过期，不用残留命中宣称证据仍可查证。

## 查询接口与三页面

Monitor 直接 HTTP 路径以新的 B 前缀 `/api/token-diagnostics/v2` 隔离，全部 GET；Console 沿用现有代理，通过 request helper 的 `/monitor/token-diagnostics/v2` 访问，最终请求路径为 `/api/monitor/token-diagnostics/v2`。旧路径及响应保持兼容。租户及来源从已有认证上下文解析，客户端筛选参数不能扩大作用域。越权定位与不存在统一按现有资源访问规范返回，禁止泄漏其他租户计数。

| 路径（相对 v2 前缀） | 用途 |
| --- | --- |
| `/dashboard` | 当前筛选窗口的已知用量、完整性、规则覆盖、字节前缀比例及参与/排除量 |
| `/tasks` | 带摘要的 Task 游标列表，支持 Agent/模型/时间/完整性筛选 |
| `/tasks/{task_id}` | Task 生命周期摘要、业务质量状态及分析修订 |
| `/tasks/{task_id}/branches` | 分支与已观测 Step，游标分页，未知顺序明确标注 |
| `/tasks/{task_id}/calls` | 分支及逻辑轮次/尝试，保留独立 Usage 状态 |
| `/contexts/{context_id}` | 构成、来源 occurrence 及捕获限制，不返回原文或密钥 |
| `/calls/{call_id}/prefix` | 已保存前缀比较、最佳候选、上下界及首差证据 |
| `/tasks/{task_id}/operations` | 操作事实及可用前后证据，失败/缺侧单列 |
| `/issues` | 当前有效命中的问题组与不能聚合的独立实例，分页 |
| `/issues/{group_key}/instances` | 验证作用域后的组内独立命中，分页 |
| `/evaluations/{evaluation_id}` | 一次评估的阈值快照、数值、缺口、引用及建议；显示历史/当前属性 |

列表游标绑定作用域、筛选和排序键；修改筛选使原游标失效。对时间范围使用 UTC 半开区间，前端按当前时区展示。默认最近 24 小时，可选 7/30 天，不支持无限区间查询。

所有返回包含查询范围及 `as_of`，分析对象包含 `data_revision`、`analyzed_revision`、是否过时与失败原因代码；批量汇总显示待分析/失败对象数。数据库不可用返回安全 unavailable，不能把失败变成空成功或零用量。数字未知用 null 配原因，已证明为零才返回 0。

Task 列表按根请求 started_at 纳入筛选，Task 分布使用已终结且采集与 Usage 均完整的 Task 全部尝试用量，Agent 归属为根请求 Agent，子分支与辅助用量计入其 Task，并说明这是执行规模分布而非同类业务效率排名。看板已知用量按物理尝试 started_at 纳入窗口，不因 Task 跨窗口重复累计；因此窗口用量与窗口内 Task 全生命周期用量不同，标题与提示明确区分。模型筛选只选择对应尝试用量，不将某模型使用过的 Task 的其他模型用量一起算入模型总量。

模型筛选下，Task 仅按是否有该模型尝试纳入列表，摘要分别返回 Task 全模型完整总量及该模型已知贡献；完整 Task 分位分布仍是全模型规模并注明筛选只选样本。筛选明确区分 `root_agent_id` 根任务归属与 `agent_id` 实际执行 Agent：前者按根 Agent 选择 Task，后者按生命周期内是否存在匹配尝试选择 Task；选中贡献仅累计匹配执行 Agent/模型的尝试。前缀过滤采用实际调用 Agent，Task 全生命周期总量仍包含全部分支与模型，避免根归属、执行贡献及前缀隔离组混淆。

Usage 完整率分母为窗口内已记录尝试，包括未知/待完成；Task 完整性按完整 Task 生命周期单独计算。类别占比使用当前 Context 完整可归因估算之和；没有可信类别或估算的条目导致分母不足时不形成该比例规则。Provider 输入/估算差额只在两侧都有值时显示，不称为完整账单核对。

Console 路由为 `/analytics/token-overview`、`/analytics/token-executions/:taskId`、`/analytics/token-issues`；原 `/analytics/token-diagnostics` 保留。执行入口没有 Task 时引导至 Task 列表，不自动挑选跨范围样本。URL 保留筛选、branch/call/context 定位与返回来源，仅允许应用内目标。问题下钻选择其实际实例引用，不能像线框固定定位调用 2。

页面展示加载、空记录、数据不可用、待分析、分析失败、历史结果、部分捕获和证据不足各自状态。键盘可操作表格下钻及调用选择；状态不只靠颜色区分，长列表分页，图例注明实际/估算及单位。延续 Console 设计规范，不新增竞争性设计系统。

## 验收与实施切分

实施按五个可验证增量交付：契约/采集 → 类型化存储 → 分析/规则 → 只读 API → 三页面联调。每个增量保留 A 回归，不依赖反馈、真实价格或服务端缓存接入。

| 验收场景 | 必须满足的结果 |
| --- | --- |
| 同起点与中间重复 | 共同前缀只从起点累计；中间重复不抬高比例 |
| 单条目末尾变化、短尾与 UTF-8 | 首差条目正确，字节区间包住真实首差，短尾终止/跨条目块不越界；不生成精确 Token 偏移 |
| 99/100/101 个候选、同时间、未来或运行中历史 | 排序稳定，最多比较 100；101 明确超限，R06 不形成完整窗口低比例结论 |
| 隔离/模型/表示/密钥版本变化 | 不跨组比较或聚合；缺必要身份列为缺口 |
| 分块区间 15%–25% 与上界 19% | 前者 R06 证据不足；后者仅在其余门槛齐备时形成候选 |
| 重试、同内容不同来源、调用缺口 | 计账逐尝试；连续轮次不借重试补足，不把相同内容合并来源，不跨缺口推断连续 |
| 压缩前后、新消息插入及摘要调用 | 只比较同一操作快照，额外摘要调用独立记账；缺侧不推导变化或节省 |
| 缺工具安全/真实 Step/进展/业务质量 | 分别执行 R04/R05/R08 降级，工具结束不替代业务步骤结束 |
| 规则门槛边界与零/空分母 | >= 与 < 边界按合同；空分母不可用，阈值版本及依据可回查 |
| 队列满、预算耗尽、DB 超时、取消/退出 | 业务继续；有界内存/采集，状态或缺口可见；不能报告完整或零消费 |
| 多实例租约竞争与评估重试 | 失效租约不提交，唯一身份幂等；新输入/新版本保留历史且不被旧结果覆盖 |
| 数据晚到、分析落后与保留清理 | 当前/历史及过时状态可见；缺证据保持缺口，全部新增表按 Token 保留边界清理 |
| 不同体量加权、跨窗口 Task 和模型筛选 | 100KB/10% + 1KB/90% 得 10.8% 左右；窗口尝试及 Task 全生命周期口径分开，模型总量不串入其他模型 |
| 三页导航、深链接与失败状态 | 问题实例定位真实调用，返回保留筛选；错误不显示为无问题，所有数据为授权范围 |

Python 使用项目 `venv/bin/python -m pytest`；沿用 Token 子系统测试，增加上述与行为有关的边界及故障用例。真实 MySQL 用隔离的临时 schema 验证事务/唯一键/租约/清理，不调用真实 Provider；环境缺失时明确未完成这一项。前端增加关键 API 状态适配与真实下钻交互检查，不把模拟线框通过当作生产联调通过。

交付包含补充后的全量初始 DDL、SWE/Monitor 契约一致性校验、部署开关/预算/缺口排查文档及三个 Console 页面。开始改生产符号前执行 GitNexus impact；提交前执行 graph detect-changes 及适当格式/测试检查。本次设计稿没有修改 A 实现或执行建表。
