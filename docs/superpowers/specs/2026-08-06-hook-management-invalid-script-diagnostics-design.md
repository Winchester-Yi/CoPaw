# Hook 管理页无效脚本引用诊断设计

## 目标

当 `agent.json` 的 Hook 配置引用不存在或不合规的脚本时，Hook 管理页仍可加载，并清楚提示受影响的 Handler。用户可以修复或删除该引用；无效配置不能通过保存或人工测试继续执行。

## 范围

- 调整 Hook 配置读取路径，使已持久化的无效脚本引用不再导致读取接口失败。
- 在读取响应中返回每个无效脚本引用的诊断信息。
- 在 Hook 管理页显示诊断信息。
- 保留保存和人工测试的严格脚本校验。

不改变脚本上传、运行时 Hook 执行或脚本路径安全边界。

## 方案

`HookManagementService.get_configuration()` 将配置结构与 ID 等基础规则正常解析，但在读取路径中收集脚本引用诊断，避免因脚本不存在、路径格式不合规或符号链接等问题抛出读取错误。响应新增可选的 `diagnostics` 字段；每条记录包含事件、Matcher Group、Handler、脚本参数和面向用户的原因。

控制台加载配置后保存诊断列表，并在 Hook 管理页面顶部展示告警。页面的编辑、删除和其他内容照常可用。

`save_configuration()` 与 `manual_test()` 保持当前严格校验：修复前保存会返回现有验证错误，人工测试也不会执行无效脚本。

## 数据流

1. `GET /hook-management/configuration` 读取已持久化配置。
2. 服务端返回配置快照和脚本引用诊断，而非因该类诊断返回失败。
3. 控制台显示配置和告警，用户修复引用。
4. `PUT /hook-management/configuration` 使用严格校验；全部诊断消除后保存成功。

## 测试

- 服务端：引用缺失脚本时，读取配置成功并返回诊断；保存同一配置仍失败。
- 控制台：带诊断的加载结果渲染 Hook 管理内容和告警，而不是整页错误状态。
- 既有合法脚本配置的读取与保存行为保持不变。

## 验收标准

- 不存在的脚本引用不会导致 Hook 管理页面加载失败。
- 页面能说明哪个 Handler、哪个脚本引用有问题及原因。
- 用户可在页面中修复或删除该配置。
- 无效脚本引用仍不能保存或人工执行。
