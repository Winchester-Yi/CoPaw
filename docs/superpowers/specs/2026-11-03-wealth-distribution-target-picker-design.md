# 财富工作台分发目标选择器

## 状态

交互设计、主要实现约定及两个新接口的请求结构已确认，已按 V3 设计实现中台组件。人员响应沿用旧接口结构及字段，真实后端联调待部署环境验证。

## 已确认交互

- 本次仅替换分行中台的分发目标选择交互；支行行长保持现有人员选择方式。
- 位于创建工作规划页面的“选择分发目标”区域。
- 左侧展示机构树，右侧以紧凑小卡片展示当前机构人员，下方以紧凑卡片按机构汇总已选结果。
- 勾选机构时同步切换右侧人员视图，查询成功后完成全选；连续勾选多个机构时展示最后勾选的机构。点击机构名称只查看，不改变选择；取消全选或待选保留当前查看机构，仍有查看需求的人员查询继续执行。勾选切换到不同机构时清空原人员搜索词。
- 人员卡片和已选机构卡片在设计稿桌面宽度下均每行展示五张，窄屏减少列数。
- 机构栏桌面宽度调整为 300px，760px 及以下为 220px，540px 及以下继续纵向排列并占满宽度。右侧人员卡片按剩余容器宽度自动减列，最多五列，保留紧凑卡片和虚拟滚动。
- 整个分行约 1200 人；人员卡片区采用固定高度和虚拟滚动，仅渲染可见行及必要缓冲，保持设计稿的紧凑卡片样式。搜索、全选、勾选状态和汇总均基于完整名单，不以当前渲染的可见卡片为范围。
- 左侧机构树不展示人数，首次仅查询机构，人员按所选机构查询。
- 支持多个机构全部人员与其他机构部分人员的混合选择。
- 人员查询成功但名单为空的机构也允许明确勾选，机构汇总显示“全部 0 人”；仅查看空机构不自动选中。支持取消、移除该机构和清空全部，状态限本次表单会话，发布依旧传实际人员，不为零人机构生成虚假人员记录。
- 整机构选择包含本级及所有下级机构；分行根机构覆盖整个分行，复选框联动所有后代（包括零人机构），之后允许取消个别人员或子机构。取消子机构后父级显示半选，再勾父级补全全部后代。
- 父子机构重叠选择时合并汇总：先选择东门支行部分人员，再全选上级罗湖支行，汇总展示一张“罗湖支行 · 全部人员”卡片，不重复展示东门支行卡片；后续取消个别人员时，罗湖支行改为部分选择。
- 后端负责最终人员去重，本次需求不要求前端额外增加名单去重流程。
- 机构复选框遵循三态选择：未选或部分选中时点击，补全为该机构全部人员；全部选中时点击，取消该机构全部人员。下方“移除该机构”直接清空对应机构范围的选择。
- 同一份计划编辑期间缓存已成功加载的机构人员名单，切换回该机构时复用名单和勾选状态，不重复调用人员接口；成功返回的空名单同样视为已加载。
- 人员名单采用本次计划编辑期间的内存缓存，勾选状态独立维护；已加载上级机构完整名单时，可结合机构树及人员实际所属机构编码筛选下级名单，不重复请求。只有下级名单时不能推断上级名单完整，查看未被完整缓存覆盖的上级机构仍需请求。
- 重新进入创建或编辑页面时重新查询最新名单；查询失败不视为成功加载，允许重试。
- 机构树查询耗时约 4–5 秒：进入财富工作台（包括看板）、身份就绪且业务角色为中台后，后台异步预加载完整机构树，不阻塞页面。运维模式未选定目标分行时不查询。
- 同一身份及分行上下文内，机构树内存缓存可跨创建、编辑计划复用；进入选择区时复用已完成结果或同一个在途请求。预加载失败不阻塞看板，选择区提供重试。
- 运维模式切换分行时，立即使旧机构树、人员缓存、已选状态及在途请求失效，重新查询目标分行机构树，不复用原分行或目标分行此前访问留下的缓存；切回先前分行同样重新查询。旧请求即使随后返回，也不得更新当前上下文。
- 真实身份或业务上下文发生变化时同样使机构树及人员缓存失效；不得回退旧分行的数据。
- 勾选尚未加载人员的机构时，先展示加载状态，查询成功后才完成全选并计入已选汇总；失败时显示重试，不影响其他机构已有选择。人员查询未完成期间禁用发布，避免遗漏正在选择的机构。
- 编辑已有规划时先回显历史已选人员及所属机构；未查询该机构完整名单前展示“已选 N 人”，复选框暂用半选状态，不宣称全部选择。获得完整名单后再判定全部或部分选择。
- 历史已选人员所属机构不在当前机构树中时，保留历史选择并单独归入“未匹配机构”汇总卡片，允许手动移除，不因机构撤并或过滤自动删除接收人员。

## 已确认接口能力

- 后端提供两个新接口，分别查询机构和按机构查询人员；约定见下文。
- 机构接口一次返回当前分行的完整机构树，只包含机构信息，不包含人员；左侧展开机构和按机构名称或编码搜索不额外请求接口。
- 可选机构由后端过滤；中台新组件不保留旧前端按机构名称包含“停用”“私人银行”“信贷部”进行排除的规则。
- 人员查询将所选机构本级及所有下级逐项列入一次请求的 `orgList`，不依赖仅传父机构隐式覆盖后代。查询分行根机构时展开完整机构树，成功批次返回这些机构的完整联合名单，无需逐级发起请求。
- 人员接口不分页，每次返回所选机构范围的完整人员名单；查询分行根机构时一次返回整个分行的完整人员名单。
- 每个人员返回其实际所属机构编码；即使通过上级机构查询，下级机构人员仍保留实际归属，用于匹配完整机构树及展示人员归属。具体字段名待新接口提供后对齐。
- 两个接口的地址和请求结构已提供；人员响应沿用旧接口的结构及字段。

## 机构接口

- 用户提供的服务接口为 `/wealth/wmadm/bbkTree`，方法：`POST`；已确认与旧接口使用同一服务，前端请求路径保留 `/zt`，使用 `/zt/wealth/wmadm/bbkTree`。统一请求层拼接后的地址为 `{API base}/api/zt/wealth/wmadm/bbkTree`。
- 请求参数：`mmOrgCode`（字符串）、`mmOrgName`（字符串）、`mmOrgLvl`（数字）、`sysId`（字符串）。
- 机构树初始请求沿用旧逻辑：普通模式的 `mmOrgLvl` 取登录上下文 `orgLvl` 并转为数字，不固定为 30；运维模式沿用现有业务上下文，目标分行初始 `orgLvl` 为 `"30"`，请求传数字 `30`。`sysId` 沿用登录上下文。
- 用户请求示例：`{"mmOrgCode":"755","mmOrgName":"深圳分行","mmOrgLvl":30,"sysId":"retailbanking"}`。
- 成功响应：`code: "200"`、`message: "ok"`，`data` 为一个根机构对象，不是数组。
- 机构节点使用 `mOrgCode`、`mOrgName`、`mOrgLvl`，子节点通过 `children` 嵌套；根节点的 `parentId` 为 `null`。级别示例同时出现字符串 `"30"` 和数字 `70/80`，适配时需兼容。
- 附加字段包括 `sysId`、`parentId`；子节点示例还包含 `vbbkNbr`、`vbbkName`、`branchId`、`text`、`leaf`。
- 完整树中以 `children` 判断是否存在下级，不依赖示例中末级仍为 `false` 的 `leaf`；不继续使用旧逐级接口或 `121516` 特殊末级规则。
- 已确认请求和响应示例为拼接数据；正式响应根机构的 `mOrgCode` 与请求的 `mmOrgCode` 一致，机构名称及后代属于对应分行。前端应核对返回根编码，不展示与当前请求分行不符的树。
- `mmOrgName` 沿用现有 `BBK_ID_MAP`，按当前业务分行编码映射名称；仓库条目仅为示例，实际环境提供完整映射，本次不补造分行映射数据。运维模式使用目标分行编码及其对应名称，不沿用真实登录分行名称。

## 人员接口

- 用户提供的服务接口为 `/wealth/wmadm/orgSaps`，方法：`POST`；前端请求路径使用 `/zt/wealth/wmadm/orgSaps`，统一请求层拼接后的地址为 `{API base}/api/zt/wealth/wmadm/orgSaps`。
- 请求体为 `orgList` 数组，每项包含 `bbkOrgId`、`mmOrgCode`、`mmOrgLvl`。
- 人员查询使用所选机构节点的 `mOrgCode` 和 `mOrgLvl`，级别规范为数字；`bbkOrgId` 使用当前业务分行编码，运维模式使用目标分行编码。
- 用户请求示例：`{"orgList":[{"bbkOrgId":"755","mmOrgCode":"102","mmOrgLvl":50}]}`。
- 支持多个机构范围；已有完整范围缓存时不重复请求。需查询父级范围时，本级和全部后代（含已缓存的部分子级）均展开到 `orgList`，以取得该范围的一致完整名单；多个范围重叠时按机构编码去重。每项使用该节点自身的机构级别。
- 响应结构及人员字段与旧接口一致：成功业务码为 `"200"`，`data` 为人员数组；沿用 `sapID`、`userName`、`branchID`、`subBranchID`、`branchName`、`subBranchName` 等字段映射。
- 批量查询采用整批成功或整批失败语义：成功业务码 `"200"` 表示 `orgList` 中全部机构查询成功，某机构无人员仍属于成功空名单；任一机构查询失败时整批返回失败，不以 `"200"` 携带部分结果冒充成功。前端失败时不接纳该批结果、不将该批机构写入成功缓存或完成全选，保留此前已有缓存和人员选择。
- 两个新接口均沿用旧接口的 `/zt` 服务前缀及统一请求层的鉴权、API base 和 `/api` 拼接规则，仅替换接口名。

## 人员请求合并与排队

- 连续机构操作采用 500 毫秒固定合并窗口，从该批首个需要查询的机构入队时开始计时，后续点击不延长窗口；窗口结束后通过一次 `orgList` 请求查询该批机构。
- 同一业务上下文内同一时间最多一个人员查询请求在途。请求期间允许继续查看或勾选其他机构，新增的查询需求进入下一批队列，不立即发起并发请求。
- 下一批从其首个查询需求入队时开始计时，排队等待时间计入合并窗口；当前请求结束时若下一批已等满 500 毫秒，直接发送，否则只等待剩余时间。
- 每批发送前检查最新选择、查看需求及缓存覆盖情况，已不再需要或已被完整缓存覆盖的机构不发送；等待期间取消勾选且没有查看需求的机构移出待查询队列。
- 批次内先合并重叠的查询范围，接口适配层再将范围展开为本级与全部后代；不会只把祖先机构作为唯一 `orgList` 项发送。
- 查询发出后取消勾选，成功返回的人员名单可以缓存，但不能因此重新选中该机构。机构加载结果与用户最新选择意图分开维护。
- 界面区分“等待加载”和“加载中”，查询成功后才完成对应机构的全选；等待队列或在途人员请求未完成时禁用发布。
- 切换分行、身份或计划编辑会话时使相应队列、定时器、选择意图及旧请求回写失效；运维切换分行仍遵循强制重新加载规则。
- 某批请求失败后结束该批加载状态，不将其机构记为加载成功或完成全选，保留已有人员选择并标记“加载失败，可重试”；后续排队批次继续执行，不被该批失败阻塞。
- 失败请求不自动无限重试；用户点击重试后，将仍需查询的失败机构重新加入队列，继续遵循 500 毫秒合并窗口、缓存检查及单请求在途规则。
- 队列清空后，若仍有用户想全选但查询失败的机构，继续禁用发布，提示重试或取消对应待选操作；不能静默忽略失败机构后发布。单纯查看人员失败、且没有待完成的选择操作时，不因此永久禁用发布。
