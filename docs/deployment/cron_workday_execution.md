# 新版任务：工作日执行与排程

当前分支已适配年份 Cron 和可执行日期区间；最新迁入范围、通知生效条件及部署检查见 [2026-11-04 适配说明](cron_workday_system_port_20261104.md)。本文末尾 2026-10-21 测试数为原提交历史，不代表本轮结果。

本提交接续共享日历底座和完成通知过滤，只接入新版用户任务的自动执行准入、
工作日排程、查询预览及表单。不包含系统任务迁移、精选案例创建入口切换或最近错误详情。

## 执行规则

- `schedule.run_on_non_workday` 保存于已有 `spec_json.schedule`，只接受布尔值。
- 未传或 `false`：自动普通、批调度在非工作日跳过；`true` 不额外过滤普通 Cron。
- **已有新版任务缺少该字段也按 false 执行，上线后将开始跳过非工作日。**
- 旧 SWE 用户任务、手动执行和系统任务不接入此用户日历过滤。
- 跳过记录在触发回执，不创建业务执行，不当作执行失败，不补跑或顺延。
- 原 Cron 的候选约束仍有效：周一至周五表达式不会自动增加调休周六的触发。

`LW` 为当月最后一个实际工作日；`nW` 从当月n号（包含当天）向前选择最近的实际工作日，
不向后、不跨月；当月无符合日期则该月不执行，短月锚点限制在月末。两者即使开启非工作日执行，仍按工作日选日；
不允许再组合星期限制。平台注册每日候选，数据库保留原业务表达式和月份限制。

2026-11-05调整：以上nW规则替代此前的前后最近规则。例如15号休息而13号、16号工作，`15W`取13号而非16号；15号本身工作则取15号。`1W`在1号非工作日时跳过当月；`31W`在短月从月末向前找。已有新版nW任务升级后也按此规则计算，不补跑已错过的日期；运行日期区间不允许时不另选后一天。只改Scheduler日历选日，不改变旧用户任务或系统任务的平台表达式规则，不增加SQL、配置或平台注册操作。

## 批调度与时间

批次仅按父任务原计划的北京时间业务日准入一次；入队快照保存日期、日历来源、规则及定义版本。
提前量只改变平台候选触发时刻，不增加内部成员二次散列。已入队成员跨日继续执行。

平台有合法原计划/触发时间时据其恢复业务时间；原固定 Body 不要求新增时间字段或 Header。
缺少可信时间时使用收到请求的时间加提前量推算，并标记 `callback_received_at`；
不能承诺严重延迟回调仍能恢复原周期日期。本次不增加按周期去重。

沿用现有外部平台北京时间前提。保留非北京时间字段和算法预览不等于平台跨时区执行已验收。

## 查询与前端

新版列表、详情、子任务列表统一计算日历预览。日历观察在任务事务外，同页复用日期结果；
展示预览预算不影响实际执行准入。无候选可返回空预览，外部失败明确标记 fallback。

新版管理表单增加非工作日开关和月末工作日选项，编辑保留多小时、自定义 nW 与原时区。
明确选择月末工作日使用北京时间。共享快捷弹窗仅在显式 managed 模式下启用日历和服务端预览，
不因此切换精选案例的实际创建入口。旧页面和旧模式保留原链路。

## 依赖与部署

不新增用户任务表字段或必配 Token。共用数据库须按已有
`scripts/sql/cron_workday_calendar.sql` 人工准备 `swe_workday_calendar`；应用不执行 DDL。
日历服务及 `/api/scheduler/cron/calendar/resolve` 已由前置提交提供。
正常结果缓存 24 小时，异常按普通周末规则兜底 5 分钟，不能准确识别降级期间的法定假日或调休。

匹配发布 Scheduler、SWE 模型与重新构建的 Console；旧用户平台入口不切换。
检查已有新版任务的开关期望，再验收实际回调。发布不代表既有平台定时器已自动重新注册。
如回退到不理解 W/LW 候选的版本，先暂停对应每日候选定时器，防止每日误执行。

## 验证入口

1. 新管理页创建、编辑每日及多小时任务，核对开关 false/true/缺省、复杂表达式往返。
2. 用受控日历覆盖法定假日、调休工作日、LW/nW、当天可执行、只向前查找、月初无候选、短月和月份限制。
3. 调用现有新版普通/批回调，核对非工作日跳过、开关覆盖及回执和执行快照。
4. 验证跨月提前批次、成员同时可执行、排队跨日不再次过滤，以及手动执行不受影响。
5. 验证列表、详情和子任务预览，以及日历异常 fallback；旧页面/旧模式回归不变。
