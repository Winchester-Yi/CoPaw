# 精选案例快捷订阅改用 Scheduler

只切换案例详情“订阅为定时任务”的创建链路；案例展示、“做同款”和旧任务不迁移。
本提交依赖前置的新版任务管理接口及工作日规则，不包含系统任务迁移或最近执行错误弹窗。

## 行为

- 创建请求改用 Scheduler，不再调用 SWE 旧创建接口。
- 保留案例标题、正文、模型、通知延迟及 `meta.subscription_key=featured_case:<id>`。
- 不由前端随机生成任务或会话 ID，由后端完成资源准备并给出权威绑定。
- 快捷入口保留每天、每周、每月，不展示非工作日执行开关及月末工作日。
- 请求组装固定 `schedule.run_on_non_workday=false`，不只依赖隐藏开关或服务端缺省值。
- 仍读取用户排程时区并使用服务端日历预览；不影响新版管理页的完整日历配置。

## 创建与重试

请求携带当前操作者、租户、来源和 Agent Header。案例来源不一致时拒绝创建。
Scheduler 返回受理后查询管理操作；操作 completed、任务 ready 且身份一致才提示成功并刷新聊天列表。
仍在处理中时提示到新版管理页查询，不把“已受理”当作资源准备和平台注册已经成功。

网络未知时保留原正文、配置和请求号；已知管理操作失败时重试原操作。
关闭、切换身份或切换案例后，旧响应不能覆盖新工作区或假报创建成功。
前端取消等待不等于取消已经受理的后台任务，结果不确定时应先查询原操作。

## 部署与验证

重新构建部署 Console，使用已匹配部署的 Scheduler 创建、操作查询/重试、详情及日历接口。
不新增数据表、字段、必配配置或 Token；不增加 subscription_key 物理列，不迁移订阅统计。

1. 案例详情点击订阅，确认时间、模型和通知延迟仍可配置，假期相关选项不可见。
2. 抓包确认只请求 Scheduler 创建，正文和案例关联键保留，非工作日字段明确为 false。
3. 验证操作未完成时不提前提示成功，ready 后刷新聊天任务列表。
4. 模拟请求超时后重试，核对内容和请求号不变；已知失败续办原操作。
5. 切换用户、来源、Agent 或关闭案例，核对迟到响应不会串到新视图。
6. 回归旧模式快捷弹窗和新版任务管理页，确认原配置能力不受此入口限制影响。

本地组件、HTTP 桩和静态检查不能替代行内网关、真实 SWE 准备及平台联调验收。
