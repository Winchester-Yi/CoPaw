# 批调度独立暂停与旧任务兼容

## Summary

为批调度增加独立的暂停／恢复状态，保留任务自身启停和调度模式的原有职责。只对属于批调度的父任务初始化整批状态，避免普通任务被误迁移，也避免升级意外启动原本关闭的批调度。

---

## Problem Frame

父任务同时承载广播配置和自身执行。当前父任务关闭会阻止新批次创建，未读保护因此可能间接阻止其他用户的子任务。已进入队列的关闭任务又可能被当作已派发，占用 Worker 直到超时。旧任务没有独立的整批暂停状态，不能无条件默认恢复运行。

---

## Actors

- A1. 管理员：管理某个批调度父任务的整批暂停／恢复。
- A2. 任务所有者：管理自身任务开关，或由未读保护自动关闭自身任务。
- A3. 调度服务与执行服务：筛选可派发任务，执行并结算结果。

---

## Requirements

**归属与兼容**

- R1. 首先根据已保存的调度模式与父子关系判断归属。普通任务不初始化整批状态，不改变其开关、普通定时器或运行方式；仅存在广播关系或历史批次，不足以认定当前属于批调度。
- R2. 批调度子任务没有独立的整批开关，不从子任务的启停状态推导整批状态；整批开关归属于对应的批调度父任务。
- R3. 已有批调度父任务缺少新状态时，首次保守继承：父任务开启则批调度运行，父任务关闭则批调度暂停，不区分手动或未读自动关闭。该初始化必须持久化且幂等；已有明确状态不得被覆盖。
- R4. 初始化完成后，任务启停、批调度模式和批调度运行状态相互独立。父任务后续关闭只影响自身执行，不停止其他启用的子任务；父任务重新开启也不得恢复已独立暂停的批调度。
- R5. 新建或由普通调度显式切入批调度时，建立明确的整批运行状态，不能让后续父任务开关变化重新触发旧任务兼容推导。

**暂停、恢复与结算**

- R6. 暂停作用于一个批调度父任务及其已有批次：停止新批次创建，停止未开始任务和重试的派发，保留原有队列和顺序。已运行任务自然收尾；暂停本身不是执行失败，不占用新的 Worker 名额。
- R7. 恢复后，原有队列按原优先级与共享 Worker 限制继续执行，后续定时正常触发；暂停期间错过的定时时点不自动补跑。
- R8. 派发前检查待执行任务自身是否关闭；已关闭任务明确终结为跳过，不重试、不计入成功或失败的 Worker 调整样本，并释放尚未用于执行的名额。结果页面应能说明跳过原因，批次统计能够正确收敛。
- R9. 区分“整批暂停等待”与“单任务关闭跳过”：暂停不永久取消队列，恢复也不复活已终结的跳过任务。暂停不改变普通／批调度模式，也不恢复子任务的普通定时器。
- R10. UI 将整批开关与父任务自身开关明确区分，仅允许有权管理该批调度的管理员操作。失败的保存不能显示为操作成功；旧客户端编辑任务时不能无意清除已经保存的整批状态。

---

## Key Flows

- F1. 首次加载旧任务。**Actors:** A3。先判定调度归属；普通任务与子任务不初始化整批状态；只有缺少状态的批调度父任务保守初始化并保存。**Outcome:** 重复加载不再次继承。**Covered by:** R1–R5。
- F2. 暂停与恢复。**Actors:** A1、A3。管理员暂停，排队任务等待、已运行任务收尾；管理员恢复，原队列重新竞争 Worker。保存失败时明确提示，不能宣称整批已经成功暂停。**Covered by:** R6、R7、R9、R10。
- F3. 任务关闭。**Actors:** A2、A3。单任务关闭后，尚未开始的对应任务被明确跳过；其他启用的任务不受影响。整批本身暂停时保留等待语义，恢复派发前仍需检查自身开关。**Covered by:** R4、R8、R9。

---

## Acceptance Examples

- AE1. **Covers R1、R2.** 普通任务无论开启或关闭，首次升级不增加整批状态；带批调度标记的子任务也不获得整批开关。
- AE2. **Covers R3.** 缺少状态的旧批调度父任务开启时初始化为运行，关闭时初始化为暂停；已有明确的暂停或运行状态保持不变。
- AE3. **Covers R3、R4.** 初始化为运行的父任务随后因未读自动关闭，整批仍运行，只跳过父任务自身；初始化为暂停的整批不会因父任务重新开启而恢复。
- AE4. **Covers R5、R9.** 普通任务显式启用批调度时才建立整批状态；整批暂停不会将子任务切回普通定时触发。
- AE5. **Covers R6、R7.** 暂停时有运行任务、待执行任务和待重试任务：运行任务自然结束，后两类保留队列但不启动。恢复不增加重试授权，不改变顺序，不绕过 Worker 限制，不补建暂停期间漏过的批次。
- AE6. **Covers R8、R9.** 子任务在入队后关闭，派发时终结为跳过而不是已派发或失败；只暂停整批则仍为等待，不永久跳过其中任务。
- AE7. **Covers R10.** 普通任务和子任务不能通过接口设置整批状态；越权请求被拒绝；旧客户端保存父任务不覆盖该独立状态。

---

## Success Criteria

- 升级不意外启动旧关闭批调度，也不改变普通任务行为。
- 初始化后父任务未读关闭不连带停止其他用户任务。
- 暂停、跳过、运行中三种行为可区分，恢复不绕过并发限制。
- 后续实现能够逐项用回归测试证明上述兼容与状态转换规则。

---

## Scope Boundaries

- 不强制中断已经开始执行的 Agent 或子任务。
- 不自动恢复旧的关闭批调度，包括因未读保护而关闭的情况。
- 不重跑历史成功任务，不自动补齐暂停期间的定时时点。
- 不改变跨批次优先级、模型 Worker 调整策略或普通任务调度模式。

---

## Key Decisions

- 2026-09-09 用户选择保守继承方案，并明确要求首先排除不属于批调度的任务。
- 缺失状态的继承只用于一次性兼容初始化，不作为长期运行时默认值，否则父任务开关仍会间接控制整批。
