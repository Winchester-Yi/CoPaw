# 模型请求可观测首批交付

Status: resolved

## 目标

让排查人员从 Run 摘要进入单次模型请求，看到实际发生的调用、每次重试的结果和已获取的用量。采集开关、正文证据后台登记及观测存储故障均与聊天执行解耦。

首批覆盖 OpenAI 兼容协议的通用适配器及 Kimi 分支，沿用独立 JSONL、MySQL 投影和授权 API。生产 SSE 三帧作为适配器回归样例。 [独立可观测总体设计](../../docs/superpowers/specs/2026-11-15-independent-agent-observability-design.md) · [生产 SSE 样例](../agent-observability/issues/05-model-call-observability.md#生产-openai-兼容流式响应样例)

## 交付契约

1. **请求事实。** 一次逻辑模型调用可包含多次项目可见的 Provider 请求尝试。每次尝试独立记录序号、父逻辑调用、真实流式模式、请求模型、响应模型、结束原因、用量、耗时和终态。重试关系限定在同一次逻辑调用内。限流等待期间取消且尚未进入 Provider 调用时，请求次数为零。Provider SDK 内部不可见的 HTTP 重试保持不可观测。
2. **流式结算。** 从可信响应字段读取实际模型和结束原因。文本结束帧之后的纯 Usage 帧仍参与同一次请求结算。输入和输出分别保留最新已获取的累计快照。首有效 chunk 和首可见文本分别计时，空帧、纯 Usage 帧和 `[DONE]` 不参与首输出计时。非流式及未产生对应输出时，时延字段返回 `null`。失败或取消保留此前已经获取的事实。
3. **业务隔离。** 会话准入、重连和重执行由业务事实决定，采集开关只控制观测事件。聊天请求直接继续执行，正文证据服务初始化、工作区登记和重试在后台进行。登记完成后新证据正常关联，提前持久化且可验证的信封仍可恢复。未建立关联的证据按现有规则标为「未留存」。观测事件只包含受控元数据。
4. **投影和展示。** `llm_calls` 按唯一逻辑调用计数，请求尝试数单独统计。Run 分别按唯一请求尝试累加已获取的输入和输出 Token。部分覆盖时显示已观测数值，某侧完全缺失时返回 `null`。历史 Run 缺请求级证据时摘要留空。请求详情按字段显示已知值，真实零值显示 `0`，缺失显示「未获取」。单次请求的 Token 合计在输入、输出均已获取时显示。

## 完成标准

- 用生产 SSE 样例贯通适配器、模型请求 Span、JSONL、隔离 MySQL、授权 API 和 Console。请求详情显示实际模型 `deepseek-v4-flash`、结束原因 `stop`、输入 333、输出 11、合计 344。
- 一次逻辑调用产生两次请求尝试时，显示 1 次逻辑调用和 2 次请求。两次分别返回 10 和 20 个输入 Token 时摘要显示 30。只有第二次返回 20 时摘要显示「已观测 20」，第一次请求详情显示「未获取」。
- 同任务交错消费两条流、跨任务消费、开始消费前关闭、流中取消与异常都有回归覆盖。每个请求按自身实际结果结算，继续保持业务响应和异常传播。
- 采集开启、关闭及观测库不可用时，重复提交、重连和实际重执行的业务结果一致。验证后台登记失败后重试，并验证成功登记后的新正文证据可关联。
- 重复、乱序和坏事件场景下有效数据仍可投影，历史缺值语义正确。Run 摘要和请求详情通过当前浏览器、Chromium 108 和适用的 `hideMenu=true` 场景验收，记录实际版本及结果。
